# Account panel overlay

The beta template styles the account dashboard and existing WebEngine user modules. It does not replace account authentication, SQL mutations, credit systems, module configuration, costs, or reset rules. The configured active/visibility flags determine available navigation; no new account operation is enabled by the redesign.

`inc/account-locale.php` contains account-related Spanish phrases adapted from the upstream MIT-licensed WebEngine 1.2.7 Spanish language file (revision `5cf16f1284abb970e29bde2a937dbec412d1bc94`). They merge into the request's in-memory language dictionary only on `usercp` routes, including success/errors used by the native modules. The configured site language is not rewritten. Existing formatted requirements retain their numeric placeholders and values.

The dashboard groups configured links into Cuenta, Personajes, Créditos y Zen and Más opciones, and preserves configured destinations and external-tab behavior. Native child modules still run through the original handler. Account data remains generated by the CMS and is never saved in a new frontend cache or browser storage.

Class portraits are original 100 × 100 assets from the same pinned upstream template, with a local deterministic URL and a text fallback on load failure. The dashboard uses inline SVG icons. The character level shown by the native My Account module combines normal and Master levels; the UI labels this value `Nivel total` rather than inventing separate values.

Legacy character-action and voting modules emitted forms wrapping table rows, invalid HTML that browsers strip. For reset, resetstats, clearpk, clearskilltree, unstick and vote, the template normalizes only that specific pattern: original forms and hidden inputs move outside the table, and controls bind to their form ID. Method, action, tokens, character/site values and submit names/values are retained. Other forms pass through unchanged. No form is submitted during verification.

Validation: native upstream modules rendered using a stub backend, translated placeholder signature checks, PHP/JS syntax, and DOM/FormData assertions for character action selection, native fields/values, bounds, hidden tokens, email/password forms and disabled navigation. Live account operations have not been executed by the redesign.

The administrator's screenshot shows a web reset maximum of 10 while a character has 20 resets. This is a real CMS/game configuration mismatch needing a separate functional audit. The redesign preserves and displays the current web requirements without claiming they match the game server.
